# ICC 参数背景下的 SANet 思路路由实验：本轮结果

已实现并运行“时变网络/算力 → 窗口编码与上报 → 未来轨迹预测 → PPO 选择模型和 ES”。这次编码器确实接受路由任务梯度，并非只在独立 AE 后接一个 PPO。当前结果支持继续研究受限上报，却尚不支持宣称任务联合训练优于简单统计量。

## 数据与环境

- 输入为 `data/icc_paper/scenario_2026.json`：按照 ICC 公开表格、图示重建的参数样本，不是作者的原始实验数据。来源逐项记录在 `docs/ICC_DATA_PROVENANCE.md`。
- 保留 ICC 的 7 个用户、4 类任务、3 个 ES、Poisson 到达、输入/输出大小、50–100 ms 截止时间、资源和有线链路参数。所有到达均计入，不截断为每时隙一个请求。
- 新增 3 种代理模型、模型质量/成本矩阵及计算量倍率。它们没有真实 LLM profiling 支撑；不同功能的 ICC 微服务也没有被当成可互换的 LLM。
- 计算工作代理是任务各服务的串行总和，部署为每个 ES 一个共享 FIFO 执行器；这不同于原 ICC 的多实例 DAG 执行。定向数据链路由所有模型与请求共享，计算、传输均会在任务执行过程中随容量变化。
- 新增相关时变链路和算力可用率。轻量服务的 Gamma 参数表示处理速率，按物理时隙更新；运行中的任务也会变速。无线接入未建模，请求从其关联 ES 开始。
- 主实验的到达率为 ICC 重建场景的 **0.05 倍**，用于当前三个串行执行器的容量尺度；同时另跑了 0.1 倍和未经缩放的 1.0 倍。不能将主实验称为 ICC 原负载实验。

## 本轮实现

每个节点使用 8 个 5 ms 样本构成 40 ms 窗口，每个样本 16 维。完整窗口报文 528 B；16 维统计量或固定 latent 报文 80 B；4/8/16 维 latent 报文分别为 32/48/80 B，均含 16 B 报头。报文实际经过共享窄带排队、发送、传播后才供路由使用。

时序 CNN 编码器配合解码器、100 ms 未来算力/链路轨迹预测器和 PPO。接收端策略使用已收到的表示、解码特征、按信息年龄对齐的预测轨迹，以及公开请求/模型信息。未来标签只进入训练损失；策略无法读取未上报的当前状态。

对照组使用同类策略网络及相同 PPO 更新预算：窗口统计量、冻结 AE 编码器、联合训练编码器。联合训练包含策略损失、预测损失与辅助重建损失；critic 特征分离梯度。事件触发及按带宽选 4/8/16 维前缀仍是固定规则，并非学习得到的比特分配。这是 SANet 启发的任务驱动压缩实现，不是完整 SANet 算法复现。

## 主结果

指标为 **质量 ≥ 0.8 且端到端完成时间不超过任务截止时间的请求数 / 全部到达请求数**。拒绝和运行结束仍未完成的请求均留在分母中。端到端从关联 ES 接收请求起计，不含无线接入、真实 token 生成或 TTFT。

以下是 3 个独立测试轨迹的均值，单位 %；只有一个训练随机种子，不能据此声称统计显著优势。主实验 16 方法 × 3 上报容量 × 3 轨迹，共 144 次评估；每次到达阶段 400 ms，另留 150 ms 排空。

| 方法 | 32 kbit/s | 64 kbit/s | 256 kbit/s |
|---|---:|---:|---:|
| 完整窗口周期上报 + 启发式 | 20.21 | 20.41 | 27.80 |
| 窗口统计量 + PPO | **35.89** | **41.91** | **35.70** |
| 冻结 AE + PPO，16 维 | 33.58 | 32.87 | 33.44 |
| 联合训练 + PPO，固定 16 维 | 28.87 | 28.57 | 31.49 |
| 联合训练 + PPO，按带宽选维度 | 34.64 | 33.77 | 31.49 |

完整报告包括各方法标准差、实际发送速率、信息年龄与所有基线，见 `runs/icc_semantic_gamma/RESULTS.md` 和 `results.csv`。不同路由器之间的差异不能全部归因于压缩。

可以观察到的收益是：32 kbit/s 下，同一联合训练模型使用短前缀后，平均信息年龄从固定 16 维的 **56.05 ms 降到 28.61 ms（约 49%）**，联合达标率从 28.87% 到 34.64%。但在相同 16 维报文预算下，联合训练尚未超过冻结 AE；统计量 + PPO 在三个容量上均有更高的主实验均值。预测轨迹与不使用预测的启发式对照也没有一致增益。

## 额外检查与限制

- 12 次负载检查：64 kbit/s，6 种方法，单测试轨迹。1.0 倍 ICC 到达强度下，联合达标率只有 **1.47%–2.37%**，说明当前串行执行器抽象严重过载；这不是仅靠更好上报能够解决的问题。
- 6 次较长运行：64 kbit/s、0.05 倍到达率、到达阶段延长到 2 秒、单轨迹。统计量 + PPO 为 **33.64%**，冻结 AE 为 **32.80%**，自适应联合训练为 **27.49%**，同样未显示稳定优势。
- 总计 **162 次评估**，其中主实验采用同种子同请求、同质量结果、同容量与 Gamma 速率轨迹配对，并检查轨迹哈希。三种策略均完成训练，权重与训练记录已保存。
- **59 个测试通过**，新代码静态检查通过。检查点重载后的所验轨迹与保存结果一致；联合编码器与冻结 AE 的权重差异及梯度测试确认任务梯度确实生效。
- 第一轮诊断曾采用每请求固定一次逆 Gamma 速率的近似，造成过强队首阻塞。本报告只使用修正后逐时隙速率结果。旧结果单独保留在 `icc_semantic_routing`、`icc_semantic_ablations`、`icc_semantic_stress`、`icc_semantic_longer` 中，不与主结果混用。
- 编码开销按 0.2 ms 配置，尚未测量；解码/路由运行时间没有加入仿真时钟。尚无真实 LLM 质量、TTFT、逐 token SLA、并发批处理或严格 SLA 保证。

下一步最需要解决的是用可信的模型推理时间/并发能力校准负载与容量，再验证任务驱动压缩能否在同等上报预算下超过窗口统计量。当前可以交付可运行方法和机制实验，尚不足以写成已验证的算法性能贡献。
