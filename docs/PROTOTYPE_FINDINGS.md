# 原型已运行：当前证据与论文定位

## 已完成

代码入口：`python -m edge_msd.model_routing.experiment`。
说明：`edge_msd/model_routing/README.md`。

已实现动态链路/计算能力、请求的传输—排队—推理—回传、真实字节的共享窄带状态通道、周期/事件上报、AE、预测器、PPO，以及 13 种对照配置。

ICC 原有 35 项测试继续通过；新增消息因果性、容量变化、单次模型选择、随机轨迹一致性、PPO 回报与质量候选筛选等 13 项检查，总计 **48 项通过**。

所有模型质量、耗时参数和请求/网络轨迹均为合成。没有实际调用或测量真实 LLM。当前编码时延使用配置值，预测器/策略 CPU 开销尚未进入仿真时钟。结果应作为原型证据，不直接用于实际 LLM 性能主张。

## 两轮实验均保留

- `runs/narrowband_mvp/`：初始 AE + PPO，PPO 为 16,384 步；测试 seeds 101–103。训练与验证均发现策略较弱。
- 独立诊断使用 seeds 2002–2003：初始 PPO 达标率为 40.0%、37.5%；启发式为 78.0%、81.0%。观察到策略选择了不少预测质量低于要求的模型。
- `runs/narrowband_refined/`：分离 actor/critic，增加启发式预训练，并按公开的质量预测筛选候选；PPO 为 32,768 步。另用 seeds 104–108 做最终评估；未按这些测试结果挑选 checkpoint。
- 修改的候选筛选和训练初始化都是工程措施，不能归因为新的 RL 理论或信息压缩贡献。当前仅一个学习随机种子，不足以评估训练方差。

两轮结果不能因使用不同测试 seeds 而直接用百分比差来证明训练改进。原始和新 checkpoint 都保留各自架构标识及训练记录。

## 新测试集的主要结果

指标为所有到达请求中“质量达标且按时完成”的比例，表中为 5 条测试轨迹均值。完整结果和跨轨迹标准差见 CSV/JSON。通信列是实际发送速率，不是假定所有方法花费相同通信量。

| 方法 | 32 kbit/s 达标率 | 64 kbit/s 达标率 | 256 kbit/s 达标率 |
|---|---:|---:|---:|
| 仅请求/模型信息 | 76.0% | 76.0% | 76.0% |
| 完整状态周期上报 | 71.4% | 77.3% | 79.1% |
| 关键统计量 + 事件上报 | 82.1% | 82.2% | 82.2% |
| AE + 事件上报 + 预测启发式 | 82.6% | 80.9% | 80.9% |
| AE + 事件上报 + 预测 + PPO | 77.9% | 78.4% | 78.4% |
| 即时完整状态启发式参考 | 84.4% | 84.4% | 84.4% |

在 32 kbit/s 容量下，完整周期报告实际发送约 32.0 kbit/s，关键统计量约 13.6 kbit/s，AE + 事件 + 预测约 13.5 kbit/s，AE + PPO 约 13.7 kbit/s。它们共享相同物理容量限制，但不是完全相同的平均发送预算。事件报告量还受策略导致的队列变化影响。

即时完整状态方法无需通信，仅为信息充分的参考，不能称为最优上界或可部署基线。

## 对创新性的判断

**当前实现是可运行的研究基础；还没有证据支持“AE + RL 优于强基线”的论文主张。**

相对于 ICC，问题确实变了：从必须执行的微服务 DAG 的部署/并行控制，变为备选模型的请求路由，且显式引入受限、滞后的状态上报和执行期间的容量变化。

但已有文献覆盖了通用构件：

- Zhuge（SIGCOMM 2022）已经研究无线快变状态下的时延预测与快速反馈：[原文](https://zilimeng.com/papers/zhuge-sigcomm22.pdf)。
- Martini（ICNP 2020）已经研究测量与控制环路过长，以及将合适的控制放进数据平面：[原文](https://zilimeng.com/papers/martini-icnp20.pdf)。
- Decima（SIGCOMM 2019）已经采用学习的状态 embedding 和 RL 进行集群调度：[原文](https://zilimeng.com/papers/decima-sigcomm19.pdf)。
- 已有 QoS-aware edge LLM routing 使用状态抽象和 DRL：[原文](https://arxiv.org/abs/2508.00234)。

所以应用场景和信息约束的差异需要由具体机制与强对照实验来支撑。单纯换成 LLM 或把 AE 接在 PPO 前面，创新论证较弱。

## 最短的后续路线

1. **先保留最强简单基线。** 当前 16 个关键统计量已很有效，不能删掉它来制造 AE 优势。
2. **明确一个方法贡献。** 优先研究按预计模型选择错误/超时风险决定“哪个节点何时更新哪些信息”，并以路由价值训练表征。固定编码尺寸下，可先改事件触发规则，避免同时引入太多学习变量。
3. **接入真实模型证据。** 至少需要 query–model 质量/成功标签与模型–设备运行时 profile。ICC 仓库本身没有提供这些数据。
4. **再扩大统计验证。** 多训练种子、独立负载/网络变化过程、相同实际通信预算下调参，校准预测和 CPU 开销。

“窄带下及时的紧凑上报能帮助路由”已获得这组合成实验支持；“学习式压缩有独特优势”“RL 优于启发式”“可保证真实 LLM 的 SLO”目前均未得到支持。
