# 4 维表征对 16 维统计量：本轮结果

这次主设置使用真正的 4 维瓶颈。100 和 200 ms 上报周期下，4 维联合训练方法在实际发送量减少 60% 的同时，取得更高的 SLA 达标率均值。20 ms 下没有保持统计量基线的均值；结果还不是普遍优势或严格非劣保证。

## 实验设置

- 所有方法使用同一个 ICC 公开参数重建场景、0.05 倍到达率和相同动态资源过程；未新增耦合过程。模型质量和工作量仍是代理配置，不是真实 LLM 测量。
- 三个节点共享 64 kbit/s 上报容量；上报周期为 20/50/100/200 ms。
- 统计量 16 维 float32，含 16 B 报头共 80 B；Proposed 4 维为 32 B，8 维为 48 B。
- 编码器输出、解码器输入、预测器输入都是真实的 4/8 维。从预训练、策略热启动到 PPO 始终使用相同维度。接收端补零只保持 actor 接口一致，不携带也不传输额外信息。
- 四种新策略为冻结 AE4、联合编码4、冻结 AE8、联合编码8。各维度内 AE 与联合方法共用同一初始预训练权重，随后独立训练。
- 16 维统计量、AE 和联合方法复用上一轮同训练设置、同预算的权重，并在本轮新测试种子上重新评估。统计量与 AE 基线同样使用预测和 PPO。
- 一个训练种子 7；三个新测试种子 241/242/243，每条轨迹到达阶段 2 秒，另留 150 ms 排空。7 种方法 × 4 周期 × 3 轨迹 = **84 次主评估**。

## 主结果

指标为质量 ≥ 0.8 且不超过任务截止时间的完成请求数 / 全部到达请求数。拒绝和未完成请求计入分母。下表是三个测试轨迹的均值。

| 上报周期 | 统计量16，80 B | Proposed4，32 B | Proposed8，48 B | 普通 AE4，32 B |
|---|---:|---:|---:|---:|
| 20 ms | 34.02% | 32.23% | 32.83% | **34.19%** |
| 50 ms | 31.56% | **31.75%** | 31.39% | 31.39% |
| 100 ms | 30.99% | **32.35%** | 29.29% | 30.06% |
| 200 ms | 22.42% | **26.44%** | 22.16% | 25.50% |

Proposed4 对统计量16的配对差值依次为 **-1.79、+0.20、+1.36、+4.02 个百分点**。

- 100 ms：3 条轨迹中 2 条领先统计量；状态年龄从 71.98 ms 降至 58.71 ms。
- 200 ms：3 条轨迹都领先统计量；各自提高 1.68、1.30、9.08 个百分点。状态年龄从 121.49 ms 降至 108.56 ms。
- 50 ms：均值接近，仅 1/3 轨迹领先；不能以 +0.20 个百分点声称已经证明非劣。
- 20 ms：均值落后，说明较强压缩没有在所有设置下都保持性能。

## 实际上报开销

| 上报周期 | 统计量16实际发送 | Proposed4实际发送 | 实际发送量减少 |
|---|---:|---:|---:|
| 20 ms | 63.99 kbit/s | 38.51 kbit/s | 39.82% |
| 50 ms | 38.40 kbit/s | 15.36 kbit/s | 60.00% |
| 100 ms | 19.65 kbit/s | 7.86 kbit/s | 60.00% |
| 200 ms | 9.82 kbit/s | 3.93 kbit/s | 60.00% |

单包 80→32 B 始终减少 60%。20 ms 时，统计量名义产生速率超过链路容量，实际发送量已被容量截断，部分未发送报告被替换，因此实际速率只减少约 39.82%。其他周期下，双方均未超出容量，实际发送量也减少 60%。

## 压缩和联合训练分别说明什么

普通 AE4 在 200 ms 时已有 25.50% 达标率，高于统计量16的 22.42%，所以全部收益不能归因于任务联合训练。短报文、状态新鲜度和低维表示本身都参与了这个比较。

更直接的联合训练对照是同为 32 B 的 Proposed4 与 AE4：100 ms 下分别为 32.35% 和 30.06%，平均差 **+2.29 个百分点**，三个测试种子都为正；200 ms 下平均差 **+0.94 个百分点**，2/3 种子为正。20 ms 下则落后 AE4。两者使用相同的报文长度和时序，逐种子验证决策时信息年龄相同。

8 维联合方法并没有随维度增加而普遍提高性能。不能从本轮结果推断 4 维就是最小充分表示，或推断更高维度必然更差。

## 限制与验证

- 只有一个训练种子、三个测试轨迹；尚未建立统计显著优势、严格非劣或全局最优保证。
- 统计量基线固定使用 float32，尚未比较量化、删减或新增耦合特征后的统计量；没有证明低于所有手工编码的最小比特数。
- 仍是 ICC 参数重建 + 代理模型环境；每个 ES 一个串行执行器，0.05 倍到达强度，无真实 LLM profiling、TTFT 或逐 token 指标。
- 编码时延统一设为 0.2 ms；解码和路由 CPU 时间不加入仿真时钟。前馈 PPO、资源预测器和现有耦合程度均沿用上一轮。
- **63 个测试通过**；检查点核对真实瓶颈、训练维度与所有权重有限。生成字节数逐条等于报告数量 × 报文长度，实际发送量不超过链路容量；不同方法和周期逐种子共享外生轨迹。
- 主评估均已完成并先写入 CSV。首次汇总时遇到 NumPy 整数的 JSON 导出错误，已转换成 Python 整数并从完整 CSV 恢复报告，原始逐轨迹 CSV 未改动。另以种子 244 做了 7 次短流程评估，验证修复后的完整命令正常退出；它们不并入主结果。

本轮支持的具体结论是：在当前环境的 100/200 ms 上报周期下，4 维联合表征实现了比 16 维统计量更低的通信开销，并有更高的平均 SLA 达标率。下一步应验证多训练种子稳定性和更省比特的统计量基线。
