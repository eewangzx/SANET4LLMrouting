# 系统模型与方法说明

本说明对应核心代码，不依赖论文实验参数。最终文稿的两层部署结构、公式 (1)–(8)、(14)–(21) 和 Algorithm 1 是方法依据；文稿未唯一规定的实现选择在下文单独说明，不把工程约定当作已证明的理论结论。

## 1. 对象和单位

`Service` 分为核心和轻量两类。核心实例串行执行任务，处理时长是显式参数 `processing_ms`。轻量实例在每个时隙抽取一次 Gamma 工作速率；实例内任务共享这一工作预算并按 FIFO 消耗它。

`TaskType.dependencies` 表示一个任务类型的 DAG：键是服务名，值是前驱列表。一个 DAG 中每个服务名只出现一次；需要重复调用同类服务时，应使用不同阶段标识。图必须非空、无环，所有前驱与服务引用必须存在。构造完成后不要修改 DAG 或场景对象；网络缓存及已求解的部署依赖它们保持不变。

`Request` 是一次任务请求；`Stage` 是该请求中的一个就绪服务阶段；`Job` 是已经分配给实例的阶段。`Instance` 是实际占用资源的服务副本。实例等待输入传输期间仍被视为忙碌并占用资源。

| 量 | 单位 / 约定 |
|---|---|
| 时间、deadline、控制时隙 | ms |
| 数据与等效工作量 | 十进制 MB |
| 有线带宽 | Gbps |
| 无线带宽、载波频率 | Hz |
| Gamma 速率 | MB/ms，shape 无量纲，scale 为 MB/ms |
| 用户到达率 | 次/秒；每时隙平均到达数为 `rate * dt / 1000` |
| 资源向量 | `(CPU, GPU, RAM, VRAM)`；各维容量与需求必须使用一致单位 |
| 维护与并行费用 | 每实例、每控制时隙费用，不是每毫秒费率 |

到达过程是在时隙边界产生 Poisson 批量请求的离散模型，不模拟时隙内连续 Poisson 到达时刻。不同方法使用隔离的到达、信道、服务和策略随机流；部署变化不会改变外生到达与信道抽样序列。

## 2. 网络与 DAG 执行

一条有线链路传输 `b` MB 的时延为：

```text
8 * b / bandwidth_gbps + propagation_ms
```

网络是无向图，按传输加传播时长选最短路径；同节点传输为零，不连通返回无穷。重复无向链路直接报错，避免图结构静默覆盖。这个模型采用逐跳存储转发，没有链路排队、带宽竞争、全网同步传输调度或结果回传。

无线接入必须显式提供 `Scenario.radio`、网关位置与带宽。带宽在关联用户间均分；自由空间路径增益与 Nakagami 功率增益形成 SNR，再通过 Shannon 速率计算上传时间。`noise_dbm` 是分配带宽上的总噪声功率，不是噪声谱密度。静态评分使用平均信道增益，这是近似，不等于对随机上传时延求精确期望。关闭无线时只跳过用户到网关的上传，不跳过有线转发。

根阶段的数据就绪时刻是“请求上传到网关的时刻 + 网关至执行节点的转发时延”。默认转发量取任务输入大小；服务显式设置 `input_mb` 时使用该值。非根阶段取：

```text
data_ready = max(parent_finish + transfer(parent_output, parent_node, target_node))
```

因此，分支可以并行，汇合必须等待全部前驱完成且输出送达。请求在全部阶段完成后结束，完成时刻为所有阶段结束时刻的最大值。

控制发生在时隙边界，传输和计算在时隙内按连续时间推进。后继阶段在下一控制边界才进入调度；因此控制粒度本身会带来等待。初始部署与控制计算不另加启动时延。

## 3. 资源与成本

设核心实例数为 `x[s,n]`、轻量实例数为 `z[s,n]`，服务资源向量为 `a[s]`，节点容量为 `R[n]`。任何执行中的部署都必须满足：

```text
sum_s (x[s,n] + z[s,n]) * a[s] <= R[n]       # 各资源维分别约束
```

`Node.light_reserve` 是调用方给出的轻量资源预留，默认全零。静态核心阶段额外满足：

```text
sum_core_s x[s,n] * a[s] <= R[n] - light_reserve[n]
```

在线轻量阶段仍可使用所有实际剩余资源，并非只能用预留部分。该约束是两阶段衔接的显式扩展，不是原文自动提供的保障。预留为零时，核心目标可能占满资源；预留不合适时，也不能保证每个轻量服务都可部署或所有任务都按时完成。

核心启动费只在初始化时收取。轻量启动费按新增实例数 `max(0, new-old)` 收取；缩容不退款。核心与轻量维护费每时隙收取。按文稿 (7) 的字面形式，并行费用作为每个轻量实例的费用，而不是乘任务数；若改变这种计费语义，需要同时修改控制目标与执行记账。

初次轻量部署同样收费，相当于令前一时隙实例数为零。这是明确的初始化约定。改变时隙大小时，调用方应相应换算每时隙价格。

## 4. 核心部署：评分与整数规划

`qos_scores` 先对每种正到达率的用户—任务组合做 DAG 动态规划。对每个服务与候选节点，用前驱最早平均完成时间和网络转发时延估计其开始与结束时间。此时只检查单个服务能否容纳，不模拟资源争用，因此这是乐观评分而不是联合 DAG 部署解。

按文稿 (15) 的指数权重分配平均到达量，再与紧迫度汇总值相乘得到 `Q[s,n]`。紧迫度使用印刷公式的 `max(ratio, urgency_floor)`，它是下限截断。后续工作量按后代服务平均处理时间求和；终点没有后代时，用一个时隙作参考分母，避免零除。

核心整数规划目标为：

```text
min sum_(s,n) x[s,n] * (deployment_cost[s] + maintenance_cost[s] - alpha*Q[s,n])
```

约束包括各资源维总占用、非负整数实例数，以及每个核心服务的总实例下限：

```text
required[s] = max(1, ceil(total_arrival_rate_per_ms[s] * processing_ms[s]))
```

这是平均并发需求的下限，不是严格稳定性条件；等负载边界通常还需要余量。它对文稿按时隙到达量的表示做了明确的占用时间折算。

二进制变量 `b[s,n]` 与实例数通过 `b <= x <= M*b` 联动，M 根据核心资源预算计算。因此 `sum b >= min_core_pairs` 表示全局非零服务—节点对数，不代表每种服务都有多副本。

没有显式指定 `min_core_pairs` 时，在最优值附近搜索最大部署多样性。允许的目标值上限是：

```text
optimum + (1 - diversity_retention) * abs(optimum)
```

这一形式兼容正负目标值。求解器没有证明最优或问题不可行时会显式报错，不静默返回空部署。最优性只针对这里的 MILP，不针对整个随机在线系统。

## 5. 有效容量与时延代理

轻量实例速率 `f ~ Gamma(k, beta)`，各控制时隙独立、每个时隙内速率恒定。工作增量为 `S=f*dt`。由 Gamma 拉普拉斯变换：

```text
EC(theta) = -log E[exp(-theta*S)] / (theta*dt)
          = k * log(1 + theta*beta*dt) / (theta*dt)
EC(0)     = k*beta
```

此解析式由所定义的随机过程严格得到。`theta` 的单位为 1/MB。数值求根采用无量纲变量 `theta*beta*dt`，减少工作量单位对根容差的影响。

但并行任务数本身不是稳态到达率。为了使用文稿 (21) 的尾概率近似，调用方必须显式指定 `ec_admission_window_ms=W`，声明以下调度代理：

```text
r(y) = y * work_mb / W
EC(theta) = r(y)
d_tail = log(r(y) / (mean_rate * epsilon)) / (theta * r(y))
g_effective(y) = max(dt, y*work_mb/mean_rate, d_tail)
g_average(y)   = max(dt, y*work_mb/mean_rate)
```

当 `r >= mean_rate` 时没有正 QoS 指数，有效容量代理返回无穷；这表示该稳态代理不可接纳，不表示一个有限任务池永远无法完成。零任务数返回零。Proposed 遇到存在轻量服务但没有显式 W 的配置会报错；PropAvg 不需要这个参数。

`W` 与速率重采样时隙 `dt` 是两个不同概念，不会自动绑在一起。实际执行仍是共享随机工作预算的 FIFO 模型；并行度只限制实例内已接纳任务数，不把速率乘以并行度。用 `work/mean_rate` 代替随机处理时延期望也是近似，不能写成 `E[work/f]`。

因此，EC 解析式正确，不等于整个有限 DAG 的 deadline 违约概率严格不超过 epsilon。要证明后者，还需要定义实际到达过程、服务依赖、排队规则和端到端概率组合方式。

## 6. 在线方法与执行一致性

每个控制边界对已到达的活跃请求更新一次虚拟队列：

```text
H[j] = max(queue_floor, H[j] + observed_age[j] - deadline[j])
```

这里明确用已观测年龄表示文稿的在线时延状态，不读取未来完成时刻。一个请求有多个就绪分支时也只更新一次；尚未到达的人工预置请求不更新。控制器不允许在同一时间重复执行。

Proposed 与 PropAvg 的部署搜索过程相同，只替换时延模型：

1. 保留全部忙实例，以此作为候选下界；空闲实例可缩容。
2. 给等待阶段分配节点与实例槽位，同时计入已有占用和输入传输等待。
3. 分配完成后，用最终共享实例负载重新计算所有已分配等待阶段的时延评分。
4. 目标为 `eta * 当前时隙成本 + sum(priority * H * 阶段时延代理)`。
5. 枚举一个新增实例的可行候选，接受最佳负增量；接受后重算全部边际增量，直至无改善或达到迭代上限。

没有安排的阶段保留在队列，使用 `deferral_multiplier * deadline + dt` 的有限惩罚，默认乘数为 2。它是为使目标在不可服务状态下仍可比较而引入的工程选择，不是原文的理论常数。

阶段评分是等待阶段的局部代理，不是全 DAG 随机完成时间的精确目标；已运行阶段只通过占用和输入就绪状态影响候选，并没有另加一项全局等待成本。贪心只检查加一个实例的邻域，不保证全局最优或长期公平性。

`Decision.routes` 给出节点，`Decision.instance_slots` 给出该服务—节点上的实例槽位。槽位顺序固定为忙实例按 ID 排序、再接空闲实例按 ID 排序；评估与执行一致。`parallelism` 是该服务—节点的最大实例占用上限。部署前检查资源、忙实例、槽位和全部路由的准入容量，非法决策不会先改变实例再报错。

LBRR 使用资源占用选节点并轮转路由；GA 用可行解修复、有界种群迭代和精英保留搜索轻量实例数，适应度包含成本、阶段时延与预计超时量。两者核心阶段使用负载均衡部署。这些是明确的对照方法实现，不附带性能排名结论。

## 7. 正确性检查范围

测试使用人工小模型，覆盖 DAG 校验和汇合时序、单位换算、无线参数、有效容量解析式、负载代理边界、资源与预留约束、虚拟队列、评估/执行实例一致性、真实工作时间和成本记账。小型核心 MILP 还与穷举最优值核对；在线贪心检查终点是否仍有单实例新增的改善。

这些检查支持代码与上述定义一致，不代替理论证明。网络争用、冷启动、故障、迁移、有限 DAG 概率界或不同并行计算语义若进入研究范围，需要扩展模型并补相应测试，不能仅改实验参数。
