# 从 ICC 仿真器到通信受限的模型路由

本文记录迁移设计。已实现的基础原型见 `edge_msd/model_routing/README.md`：包括动态环境、窄带消息、AE、预测器、PPO 和基线；下文中任务驱动编码、学习式上报及部分模型扩展仍属于设计，不能理解为均已实现。合成实验不构成真实 LLM 性能或算法创新结论。

当前方向已按后续讨论更新为：**快速变化的网络/计算状态下，压缩上报、短期预测与滚动模型路由**。AE + RL 是基础版本；第 13 节进一步明确事件触发上报、预测误差及计划有效时间的关系。文中的 RRL 暂按强化学习路由器理解；若具体采用 recurrent RL，则对应第 12 节的历史观测策略。

审阅版本：

- ICC：`zhujuan2/edge-msd-core`，`682f41857fa5dd7a35be4757567f44e83a847207`。
- SANet：`WirelessAIatHUST/SANet`，`60d9b3c1db02aa2018e67b0020a0feb57d9e3d73`。
- 本轮验证：ICC 原有测试 `35 passed in 2.26s`；`python -m examples.minimal` 成功。
- ICC 仓库提供独立于数据集的核心仿真器和合成示例；上述检查不等于复现论文实验。

## 1. 首版研究问题

固定一组已经部署好的模型端点，每个端点对应 `(model_id, node_id)`。同一个请求可以交给多个能够完成同一任务的模型，模型之间存在质量、计算开销及资源需求差异。

请求到达后，路由器根据请求特征、模型静态信息以及**实际收到的边缘状态消息**选择一个端点。各节点在本地把高维历史状态压缩成有限长度的消息；消息经有限速率的上报通道到达中心。

研究的核心问题是：当状态变化快于传统更新机制、派单计划可能提前失效时，如何在给定上报预算下保留和更新决策相关信息，预测短期可用服务能力，并及时调整后续派单，使质量、deadline 达标率与推理成本保持较好水平？

这里的压缩对象是控制面的网络/计算状态，不是请求正文、模型权重或推理结果。不能通过缩小 ICC 的 `TaskType.input_mb` 或 `Service.output_mb` 代替状态压缩。

首版采用固定部署、单次模型选择、每端点 FIFO 队列。部署优化、模型迁移、连续 batching、KV cache 和多阶段协作可以后续扩展；首版的结论应限于实际实现的推理服务模型。

## 2. 源码中的关键边界

| 现有位置 | 当前语义 | 对迁移的影响 |
|---|---|---|
| `models.py:TaskType.dependencies` | DAG 中每一个服务都必须执行 | 多个备选模型不能直接作为多个 DAG 节点，否则会执行全部模型 |
| `models.py:Request` | 请求只有任务类型、到达时间和 DAG 执行状态等 | 缺少请求 embedding、模型能力要求、输出长度预测和质量评价数据 |
| `models.py:Decision.routes` | `(request, service) -> node` | 服务已确定，动作没有“选择模型”这一维 |
| `controller.py:Controller.step` | 过滤出 light 实例和 light 阶段，优化在线部署等 | 只替换这个方法不会接管核心模型选择 |
| `simulation.py:Simulator._route` | core 分支自行选择同服务的空闲实例 | 核心服务分发绕过 `Decision.routes` |
| `simulation.py:Simulator._complete` | 所有 DAG 阶段完成才结束请求 | 新任务应在所选模型执行及所定义的回传完成后结束 |
| `simulation.py:Simulator._advance` | core 固定 `processing_ms`；light 使用 Gamma 工作速率 | 当前不是请求相关的模型推理时间，更不是 prefill/decode 仿真 |
| `network.py:Network.delay` | 静态有线最短路径，结果缓存 | 不含链路队列和流量争用；增加请求数不会自动使有线带宽变差 |
| `simulation.py:Simulator.run` | 内部直接持有并调用 `Controller` | 新接口需要明确隔离环境真实状态和路由器可见观测 |
| `simulation.py:Simulator.results` | 完成率、deadline、已完成请求时延和实例费用 | 缺质量、每请求推理费用、上报字节、观测新鲜度等指标 |

尤其不能给 `Controller` 加一个神经网络后，把现有 `routes` 改称 model routing。模型候选关系、动作的执行、服务时间和评价目标都需要一起改变。

辅助增加 `examples/model_routing_minimal.py` 和针对新环境的语义测试。学习代码宜作为可选依赖，例如 `routing = ["torch"]`，让原 ICC 仿真不强制依赖 PyTorch。

`placement.py` 的资源校验可以继续使用。其 `place_core()` 与 `core_requirements()` 的目标建立在“DAG 中每个服务均需执行”的需求上，不应直接充当备选模型部署优化器。首版手工指定可行部署即可。

`Network` 构造时依赖完整 `Scenario`。第一版可以保留合法的基础场景用于网络计算；如果要解耦，则抽取独立的拓扑/无线配置，并让旧 `Network` 包装该组件。不要为了复用网络而伪造互为备选模型之间的 DAG 依赖。

## 4. 接口与信息可见性

建议的接口草图：

```python
# 以下是设计签名，不是当前仓库已经存在的 API。
router.select(request_view, observation, endpoint_catalog) -> RouteDecision

local_encoder.encode(local_history, byte_budget) -> ReportPacket
report_channel.send(packet, generated_at_ms)
report_cache.receive(packet, received_at_ms)
receiver.decode(report_cache, now_ms) -> RoutingObservation

environment.dispatch(request_id, decision)
environment.advance_to(next_event_ms)
```

每个模型端点内部可以有多个副本，先由固定 FIFO 调度器处理副本分配；router 首版只选择模型—节点对。请求一旦接受路由，不应每个时隙重复路由或重复计费。

| 对象 | 应包含 | 不应暴露给在线 router |
|---|---|---|
| `RoutingRequest` 的公开视图 | 请求 ID、到达时间、deadline、输入大小、输入 token 数、任务类型/embedding、可选质量要求 | 未执行模型的真实回答质量、真实最终输出长度 |
| `ModelSpec` | 能力类别、静态资源、公开价格、训练得到的质量/耗时预测器 | 测试集每个 query 的真实质量标签 |
| `EndpointSpec` | 模型与节点标识、固定副本数和公开部署状态 | 绕过上报直接取得的实时队列或空闲资源 |
| `RoutingObservation` | 到达消息的 latent/解码特征、采样时间、消息年龄、缺失标记 | 仿真器的最新全局状态引用 |
| 环境私有数据 | 真实队列、事件、评价标签、执行时采样的耗时 | 这些数据可以用于离线监督与事后评价，不能成为在线输入 |

静态能力和部署可以构造候选 mask。动态容量、链路状态等若没有通过观测传给 router，不能再用真实值做“免费”的动态 mask。环境收到动作后仍需校验；若过时观测导致拒绝、重试或超时，按明确规则记录其代价。

拒绝与等待应使用不同的显式动作/状态；首版可只支持选择端点，以及无候选时的显式拒绝，减少不必要的动作空间。

## 5. 高维状态从哪里来

先定义实际可测的状态，再确定输入维度，不能把少量标量重复拼接后声称高维压缩。

一个节点的本地状态可以包括：

- 各模型端点的等待数量、正在运行数量、按可观测信息估计的排队工作量。
- 队列中各请求的输入长度、任务类别、deadline 剩余量及相应分布统计。
- GPU 利用率、显存使用、可观测的服务吞吐历史。
- 本地相邻链路的速率、时延、丢包或流量测量历史。
- 最近一段时间的到达率、请求类别分布和状态变化趋势。

首版可以使用固定长度特征和缺失 mask。若研究重点包含变长请求队列，再换成 set encoder；局部输入只能包含该节点真正能观察到的信息。

建议第一版张量：`[batch, node, history, feature]`。在每个节点本地用小型时序 encoder 汇总历史，得到 `[batch, node, d_model]`；随后执行 SANet 式 latent 投影与重要性选择。共享 encoder 权重可以跨节点训练，但不能在发送前读取其他节点的原始状态。

当前 query embedding 在中央 router 与各节点摘要融合。首版用路由任务损失训练周期性摘要，并不意味着每条摘要都依赖某个即时 query。若以后做 query-conditioned 编码，需要明确 query 如何发送至各节点并计算相应开销。

## 6. SANet 需要怎样改

对应文件：`SANet/models/model_shared_transformer.py`。

1. 借用 `BandwidthAdaptiveCompressionModule` 的 latent 分支、importance 分支和 hard top-k/straight-through 思路。
2. 重写输入适配器。现有 `MultiTaskTransformerShared.forward()` 固定切片第 0、1、2 个特征；仅改变 `input_dim` 不会接入新的高维状态。
3. 拆开发送端和接收端。现有 `forward()` 在同一进程完成门控和解码，返回恢复到 `d_model` 的 dense tensor；`.encode()` 单独调用则没有执行 importance gating。
4. 发送选中 latent 的值、索引以及必要元信息，而不是发送一个许多元素为零的完整 dense tensor。接收端 scatter 后再解码；也可以直接用 latent 训练 router，作为消融比较。
5. 现有 top-k 对每个时间 token 单独应用。若发送整个历史窗口，实际值数量为 `history * k`，不是 `k`。本设计先在本地汇总历史，再按每节点每消息预算选择通道。
6. 当前 hard top-k 使用硬 mask 统计 `used_bandwidth`；整数预算 k 下通常恰好选 k 个，因此其 overflow penalty 为零，不能靠这个项学习“减少发送量”。固定字节预算版可以直接硬约束；若研究可变消息长度，需要新的可微码率代理与真实序列化记账。
7. SANet 原训练入口是多任务时序预测。这里改为端点评分/路由监督，不直接沿用原来的三路预测损失和数据窗口切分。

最小结构可以使用本地 MLP/GRU encoder + 固定维度 latent + 中央离散动作策略。当前方案先做普通 AE 与 RL，再增加 SANet 式重要性门控和任务驱动训练；大型 Transformer 与共享多任务层暂不要求。

## 7. 通信预算必须变成消息与到达时间

压缩流程为：本地采样 → encoder → 打包 → 上报队列 → 传输/传播 → 接收缓存 → router。

实际报告大小按序列化后的 `len(packet)` 统计，至少包含：选中值、通道索引/位图、节点标识、采样时间，以及量化需要的参数。预算需明确是每消息字节、每节点每周期字节，还是全系统 bit/s；它们不是同一个量。

例如某个明确的假设协议采用 16 字节头、float16 latent 和 uint8 索引，每条消息为：

```text
packet_bytes = 16 + k * (2 + 1)
```

这只是协议算例，不是当前实验结果。uint8 只适用于索引范围可表示的 latent；如果使用额外 scale、padding 或更大索引，其字节也要计入。原始状态对照应采用相同的头部计费与明确的数值精度。

用共享 FIFO 上报链路作为首版即可：消息的发送开始不早于生成时刻和链路空闲时刻，发送持续时间由真实消息长度与链路速率计算，传播之后才能更新接收缓存。对过时报告、缺失报告和预热阶段应采用统一规则；不要在起点免费送给某一方法完整新鲜状态。

状态年龄应从采样时间计算，而非仅从接收时间计算。小消息可能改善新鲜度，但只有通道速率、排队与报告周期确实构成瓶颈时，才有明显路由增益；若所有完整报告都能及时送达，压缩可能只有通信节省，甚至降低路由质量。

首版可以将上报通道和请求数据通道分开建模，只主张“有限状态上报下的决策性能”。若要主张压缩缓解数据面拥塞，则需要在同一链路上显式模拟二者竞争。修改有线速率时还要处理 `Network.delay` 的静态缓存失效。

## 8. 推理服务与质量数据

现有 `processing_ms` 与 Gamma 速率可以用于最初的接口验证，但正式模型路由实验需要请求相关的 profile。

至少准备：

| 数据 | 内容与使用边界 |
|---|---|
| 请求集合 | task/query ID、类别或 embedding、输入大小、输入 token 数；到达轨迹与 deadline 可单独生成 |
| query–model 评价 | 各候选模型在同一请求上的回答质量或成功标签；用于训练与评价，不直接给在线 router |
| model–device profile | 不同输入/输出长度、设备和负载下的耗时与资源测量；为环境和在线预测器分别提供接口 |
| 输出与费用 | 每模型输出大小、实际计费规则、预测输出长度与实际输出长度的区分 |

若对象是 LLM，可以先采用 profile 驱动的非抢占 FIFO 推理：运行时依赖输入长度和执行时的实际/采样输出长度。在线路由使用长度预测，不偷看实际输出。连续 batching、prefill/decode 竞争和 KV cache 若未实现，就不报告对应调度结论或伪造 TTFT 指标。

端到端时延要定义清楚：用户上传、路由器耗时、转发、等待、执行和结果回传哪些被计入。当前 ICC 没有结果回传；要报告用户收到结果的时延，必须新增该部分。CPU encoder/router 开销可先作为显式参数，再用实际模型测量校准。

## 9. 训练路线

按照 AE → RL → 任务驱动微调的顺序实现。

1. 固定部署和物理环境，使用轮转、负载策略和多种负载场景采集节点本地历史，避免预训练数据只覆盖一种路由行为。
2. 用仅在训练集拟合的标准化器处理不同量纲，对真实有效特征训练 AE 的重构目标。第一版使用确定性 AE 和固定长度 latent；训练输入包含缺失 mask。
3. 冻结 encoder，在包含真实报告长度、延迟和接收缓存的环境中训练 RL。策略读取已收到的 latent、状态年龄、请求信息与模型静态信息，不读真实全局状态。固定候选池可先采用 categorical PPO；这里是工程选择，不是预期性能最优的结论。
4. 评估普通 AE + RL，区分压缩率、重构误差和路由收益；重构最好的 AE 不一定带来最好的路由。
5. 再通过策略/价值学习或路由价值预测辅助目标更新 encoder，保留适量重构损失。可随后增加 SANet 式 importance gate，与相同总字节数的普通 AE 比较。
6. 微调阶段按 rollout 固定 encoder 版本，保存生成已到达报告所用的历史输入及时间关联，训练时保持观测因果关系；不能让策略获得消息尚未到达时的状态。若只把 detached latent 传给 RL，RL 梯度不会更新 encoder。
7. 使用更新后的 encoder 重新采集闭环轨迹；评估时冻结权重。普通 AE 冻结方案与联合训练方案均保留为对照。

完整状态评分器可以作为可选的热启动/辅助教师，但不是长期最优 oracle。真正的反事实 rollout 若使用随机服务过程，需要显式固定/耦合外生随机样本，不能仅认为相同 seed 自动保证所有策略看到同一服务轨迹。

按 query ID 划分质量数据，按独立轨迹/时间区间划分状态数据；重叠历史窗口不能跨训练/测试边界，归一化器只在训练集拟合。

## 10. 对照、指标与实现顺序

主对照：

| 方法 | 用途 |
|---|---|
| Query-only router | 判断网络与排队状态是否提供额外价值 |
| 即时完整状态 router | 参考完整新鲜观测的表现，明确其不受上报限制 |
| 受相同通道约束的 raw-state router | 衡量真实报告大小与陈旧观测的影响 |
| 手工统计/PCA/普通 AE 摘要 | 排除仅靠降维或简单统计就能取得同等效果的情况 |
| SANet 式任务驱动摘要 | 检验同样通信预算下是否更能保留路由相关信息 |

模型池、请求数据、推理物理过程、路由目标和训练数据范围应对齐。通信基线同时比较同周期下的消息开销，以及同 bit/s 预算下的报告频率/状态年龄。hard top-k、random/magnitude 选择和不同 k 可作为消融。

主要指标：质量达到阈值且按时完成的请求比例（分母为全部到达请求）、完成质量、超时/拒绝/pending、完成请求 p95 时延、每请求推理费用、实际报告 bit/s、观测年龄、encoder/router 耗时。不能只统计已完成请求的平均延迟，否则可能把丢弃困难请求误当成改进。

建议按以下顺序实现：

1. **路由环境**：固定模型端点，两个质量/速度不同的模型即可验证；模型动作确实改变执行端点和结果。使用合成 profile 的结果仅作为功能验证。
2. **有效参考**：接入请求质量和运行时 profile，跑通 query-only 与完整状态策略，确认存在值得学习的路由选择差异。
3. **状态上报**：先传原始状态，验证消息未到达时 router 不可见、队列与字节记账、动态状态不会绕过接口泄漏。
4. **普通压缩与 RL**：先预训练 AE、冻结 encoder 后训练路由策略，并加入相同通信预算的固定统计/PCA 对照。
5. **任务驱动与 SANet 适配**：微调表征并引入可选的重要性压缩，验证相同字节预算下的决策价值和消息新鲜度。
6. **研究实验**：改变上报预算、节点数、负载突发和状态变化速度，寻找收益区间与失效区间。

关键测试应覆盖：一次请求只执行一个选中模型；端点队列不超卖；传输与执行时间正确；旧报告不能覆盖更新的样本；消息未到不能使用；预算包含索引/头部；策略不访问真实评价标签；完成、拒绝与 pending 总数守恒。原 ICC 35 个测试继续作为回归检查，但不能替代这些新语义测试。

## 11. 可能形成的贡献

最值得检验的主张是：**在有限上报带宽与陈旧状态下，针对模型路由训练的分布式摘要，在相同通信成本下比通用摘要保留更多决策价值。**

可进一步研究摘要长度/上报频率随负载和决策不确定性调整，但应在固定预算版有效后再加入。若只有“接入 SANet 后压到低维”，创新性仍然较弱；如果没有明显通信瓶颈或候选模型差异，实验也可能没有收益。

与 ICC 的边界是动作和问题目标变化：从微服务部署/并行控制转为备选模型选择与有限观测下的决策。与 SANet 的边界是任务目标和闭环机制变化：从其原有任务预测结构转为质量—时延—费用相关的模型路由、真实上报延迟与队列反馈。

这些是待验证的研究假设，不应在实验前写成已证明的新颖性、QoS 保证或具体提升百分比。

## 12. 窄带 AE + RL 的具体设定

### 12.1 上报对象与通道

“上传全文”在这里指上传完整原始网络/计算状态。请求正文仍按原来的任务数据通道传输，其大小不因 AE 而减少。

第一版给状态上报显式分配较小的可用速率，可以是独立控制通道，也可以是总链路的一部分固定预算。需要说明这个预算的场景依据；初期合成实验中的速率不能直接称为真实网络测量。

下面仅是单节点、固定协议的算例，不是仿真性能结果。假设本地状态确实包含 1024 个 float32 数，AE 输出 32 个 float32 数，公共消息头为 16 字节，上报可用速率为 128 kbit/s，每 100 ms 采样一次：

| 消息 | 大小 | 单纯发送时间 | 按采样频率全部发送所需速率 |
|---|---:|---:|---:|
| 原始状态 | 4112 B | 257 ms | 328.96 kbit/s |
| AE latent | 144 B | 9 ms | 11.52 kbit/s |

计算式：`serialization_ms = 8 * packet_bytes / rate_bps * 1000`。上述值不含编码、排队和传播。固定维度 AE 无需 top-k 索引；如果改为可变通道选择，必须另计索引。

同一采样频率下，完整报告的供给负载超过通道容量；若全部 FIFO 排队会持续积压。合理对照还应允许完整报告降低发送频率，或者只保留最新待发送报告；压缩报告使用相同规则。已经开始传输的报文是否允许中断也要统一，不能只给一种方法免费抢占。

多节点共用通道时，负载比为 `rho = sum_n(8 * packet_bytes_n / report_period_seconds_n) / shared_rate_bps`。固定大小/周期例子中它表示平均提供负载；不能把 rho < 1 当作所有随机网络的无条件稳定性证明。

实验应覆盖不同带宽和状态变化速度：完整报告也能及时到达、完整报告明显变旧、严重受限等区间。低维不保证更优；状态变化很慢或完整状态很小的时候，普通报告可能已经足够。

### 12.2 决策观测、动作与奖励

令节点 n 在 tau_n 时刻采样，编码为 z_n(tau_n)。只有报告已于 t 之前到达时，策略才可读取它。观测包含：

```text
o_t = [request_features,
       {(received_latent_n, t - sample_time_n, missing_flag_n)},
       public_model_profiles]
action_t = selected (model_id, node_id)
```

策略直接使用 z，在线不必先通过 decoder 重构完整状态；decoder 主要用于 AE 训练与重构评价。质量相关的 query 特征和模型能力信息仍然需要，网络 latent 不能单独表达所有模型选择依据。

由于状态压缩与通信延迟，o_t 通常不是保证满足马尔可夫性的完整状态；应按部分可观测问题处理。第一版使用 latent + 状态年龄；随后对照 GRU/LSTM 的历史策略。循环策略可结合历史观测、先前动作和经过时间，但不能保证恢复全部丢失信息。

RL 的合理性来自动作的后续影响：请求分配会占用端点资源，改变后续请求的队列与时延。若环境每次决策后重置负载，就没有把这个长期效应建进去。

奖励以系统实际结果计算：按时且质量达标的完成收益，扣除推理费用、排队占用、拒绝或超时等代价。每项按时间、费用基准归一化；明确费用何时产生、成功何时计入、超时是否只罚一次。不要让 router 在动作前读取真实质量或未来完成时间。训练中可由仿真器在结果发生时提供奖励；实际部署中质量反馈是否可得需要单独说明。

固定时隙接口便于统一控制与奖励累积。若实现逐请求/事件接口，相邻动作间物理时间可能不同，应明确折扣和时间成本的计算，避免在同一批请求的每个动作中重复累计整段时间费用。episode 结束时的 pending 不能无代价消失；采用统一的排空/截断规则和剩余任务处理。

### 12.3 两种 AE 的研究区别

普通 AE：`L_rec = mean((normalized_x - decoded_x)^2)`，再用冻结的 encoder 训练 RL。这是功能原型和必要对照。

任务驱动版本：`L_total = L_RL + alpha * L_rec`，其中 L_RL 表示实际采用的策略/价值训练目标，且训练图允许更新 encoder。重构损失、策略损失与价值损失的权重和优化路径需要实现时具体定义。固定维度/精度下的报告大小是硬约束，不应加入一个对所有样本都恒定的“码率损失”并期待它产生优化作用。

直观上，普通重构误差可能更关注数量多或变化大的特征，却忽略临近饱和的某个模型队列或接近 deadline 的少数请求。标准化能缓解量纲问题，但仍不能保证重构误差与路由收益一致。用 RL/价值辅助目标训练后，需要实验证明 latent 更有利于决策。

因此，AE + RL 可以作为首版实现，但不能单独当作新颖性主张。更具体的研究点是有限上报下的表征—新鲜度—长期路由收益关系。

### 12.4 相关原始研究

- [Improving Sample Efficiency in Model-Free Reinforcement Learning from Images](https://arxiv.org/abs/1910.01741)：AE 辅助的表示学习与 RL 已有研究；其图像控制实验不直接证明本网络路由方案有效。
- [Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347)：候选策略训练算法来源；选择 categorical PPO 是本设计的实现判断。
- [Deep Recurrent Q-Learning for Partially Observable MDPs](https://arxiv.org/abs/1507.06527)：用循环网络处理部分观测的参考；不意味着 RNN 能保证恢复马尔可夫状态。
- [Quality-of-Service Aware LLM Routing for Edge Computing with Multiple Experts](https://arxiv.org/abs/2508.00234)：已有状态抽象结合 DRL 的边缘模型路由研究，贡献应进一步聚焦通信约束和决策相关压缩。

## 13. 快变状态下的预测与滚动调度

### 13.1 场景与时间尺度

场景动机是：管理器依据一份报告安排未来约 2 秒的派单，但真实链路、外部负载或可用服务能力约 1 秒后已发生变化，原来的选择可能不再合适。这些时间是问题描述中的例子，不是仿真中预先保证的变化规律。

需要分别建模四个时间尺度：

| 时间尺度 | 含义 | 设计作用 |
|---|---|---|
| 本地检测间隔 | 节点多久测量一次实际状态 | 决定是否能及时发现变化；少上报不等于少检测 |
| 报告间隔和传输延迟 | 何时产生消息、何时到达中心 | 决定管理器何时获得修正信息 |
| 决策更新间隔 | 何时重新选择后续请求的模型端点 | 决定收到变化之后多久真正改变派单 |
| 预测时域 H | 向前估计多长时间的网络和服务能力 | 决定规划考虑的未来范围，不代表状态将在 H 内保持不变 |

即使刚收到一份准确报告，未来仍可能改变；压缩主要减少消息开销与传输等待，不能消除未来不确定性。状态数值改变也未必使模型选择失效，需看变化是否影响 deadline、排队、质量或费用目标。

### 13.2 三个相互衔接的组件

**本地压缩与触发上报。** 节点按较快的本地周期检测，用 AE 编码。第一版使用可解释的触发规则：本地队列或可用吞吐变化超过阈值、越过拥塞阈值，或达到最大静默时间则上报。保留最低发送间隔、通信预算和待发送报告替换规则，避免变化时同时产生大量积压消息。周期心跳作为兜底。

之后可以用局部预测残差或预计决策影响代替简单幅度阈值。若触发器需要知道中心当前预测，必须定义已确认报告版本、反馈/ACK 或同步模型，并计入反馈开销；不能让边缘节点免费读取中心全局状态。第一版可先使用本地已知量，避免不明确的同步假设。

**中央预测。** 使用已到达 latent 历史、时间戳、状态年龄及中心自身已做出的路由动作，先估计当前状态，再预测未来多个时间点的链路可用速率、端点负载、等待时间等。预测目标优先选择会改变模型选择的量，而不是把所有原始状态都逐维预测一遍。外部流量和信道可用历史预测；自己派单产生的排队变化需要在状态演化/候选动作评估中显式考虑。

预测器可先采用 GRU。除了均值，输出分位数或经验不确定性，用独立验证轨迹检查校准。越往远处预测通常越不可靠，不能把一个点预测解释为 2 秒的服务保证。无法由过去预测的突发变化，需要快速检测和保守派单，不能要求预测器事先知道。

**滚动路由。** RL 输入已收到的摘要、状态年龄、预测摘要/不确定性、请求与模型信息。可以向前看 2 秒，但每 100 ms 或在重要报告到达时重算后续派单；这些具体间隔是待扫描的设计参数。首版报告触发器固定规则，RL 负责路由，待收益确认后再考虑让策略联合决定报告时机或摘要长度。

以上使用滚动规划思路。若策略只把预测作为输入、并未显式求解有限时域优化，不应称其为已经实现了 MPC。可以额外做一个预测驱动的启发式或 MPC 对照，判断收益来自预测还是策略学习。

### 13.3 动作的可撤销性

“只执行下一个 100 ms 的派单计划”意味着每个更新周期重新决定未来请求送到哪里，并不意味着执行超过 100 ms 的请求会自动暂停或迁移。

首版维持每请求一次模型选择：已运行请求留在原模型端点，新的请求按新策略分配。尚未派发请求可以改变选择；已入队请求是否允许重路由，需要另行定义取消、传输和资源释放语义。模型切换、重启推理和 KV cache 迁移若进入范围，必须计算成本。

对于预计要执行 2 秒的单个不可迁移任务，滚动更新后续派单不能保证挽救它。初次选择必须考虑这段执行时间内的预计累计服务量、排队和风险余量；必要时选择更稳健的端点。没有分布假设、校准和约束验证时，不主张严格 SLO 保证。

### 13.4 仿真中的物理演化

当前 ICC 的有线延迟使用静态缓存，core 处理完成时间由固定 `processing_ms` 给出。为了验证本节场景，新环境至少应让所研究的链路/服务可用能力按细粒度时钟推进，独立于报告和决策时钟。

例如数据传输保存剩余 bit，每个物理步根据当时实际可用速率扣减；容量在传输中下降会真实推迟完成。研究动态服务能力时，同样按剩余工作和实际服务预算推进，或接入能反映相关因素的运行时模型。不能只在日志中改变“网络状态”，执行仍使用派单时一次计算的固定完成时间。

状态过程同时覆盖有时间相关性的平稳段、趋势变化和随机突发；变化时刻不能永远固定在 1 秒，否则模型可能只记住时间。独立无记忆噪声不应被设成可准确预测。改变状态相关时间、突发强度和上报容量，检查预测何时有效、何时主要依赖快速反应。

建议新增/细分 `StateProcess`、`ReportTrigger`、`StatePredictor` 三个接口，保持其与 `RoutingEnv`、通信队列及 RL policy 分离。最小实现先固定 latent 长度和触发阈值，避免同时优化所有变量。

### 13.5 如何分离各项增益

固定相同 AE、模型池和路由策略类别，至少比较四种配置：周期上报无预测、事件上报无预测、周期上报加预测、事件上报加预测。各方法的阈值/周期应在同一平均通信预算下调优，并报告实际字节与突发峰值；另保留原始状态上报和简单压缩对照。

除质量、超时、费用、报告字节外，新增：真实重要变化发生至被检测、报告到达、调整派单的各阶段延迟；各预测时域的误差与不确定性覆盖率；变化前后 deadline 达标情况。状态年龄只能描述报告有多旧，不能单独代表信息是否仍对决策有用。

研究主张可聚焦为：针对快速变化的网络，依据决策相关变化更新紧凑状态，并利用带不确定性的预测滚动调整模型路由，在有限上报预算下减少失效信息造成的服务损失。

事件触发预测控制和任务相关信息新鲜度已有基础研究，不能把三者的简单组合称为首创；本项目的新颖性需落实在模型路由中的具体信息选择、触发规则、预测利用方式或可验证的收益机制上：

- [Towards Event-Triggered NMPC for Efficient 6G Communications: Experimental Results and Open Problems](https://arxiv.org/abs/2409.18589)：事件触发与预测控制共同设计的实验参考，应用对象是网络化控制而非本项目的模型路由。
- [The Age of Incorrect Information: an Enabler of Semantics-Empowered Communication](https://arxiv.org/abs/2012.13214)：信息年龄之外考虑内容错误及任务相关价值的参考，不能直接将本文的自定义路由指标等同于该文的 AoII。
