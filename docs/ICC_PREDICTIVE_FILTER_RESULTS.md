# 本轮结论：联合训练可实现，路由增益尚未成立

**指标范围纠正：** 本页是历史原型的质量与 deadline 联合达标结果，不是 ICC 原 SLA 的实验结果。后续主问题沿用 ICC 的完整任务端到端 deadline；定义与迁移范围见 [SLA 对齐说明](ICC_SLA_ALIGNMENT.md)。现有权重与原始数值不变，尚无迁移后的新结果。

已经实现并运行 X→Z→未来资源预测、可训练 importance filter、PPO 路由以及 PPO 选择上报维数。两批训练各包含 6 个方法 × 2 个训练种子 × 60 次 PPO 更新；热启动版完成 216 次主测试评估。72 项测试通过。目录名中的 stable 仅是历史命名，不代表已验证 PPO 收敛。

**本轮不能作为算法优越性的正向证据。** 加入统一公共规则热启动后，SLA 曲线变平，但策略仍基本执行热启动规则；完全不上报的规则达到了同样的测试 SLA。

后续的固定观测分布、critic 和负载校准见 [PPO 与 tradeoff 诊断](ICC_PPO_TRADEOFF_DIAGNOSIS.md)。该诊断确认种子 7 尾段仍明显漂移，并找到了保留 ICC deadline 参数及当时原型质量门槛时有节点选择收益的中载工况；未重训或改写本页的主测试结果。

## 三个实现问题

1. **SANet 的 importance filter 不是 IB 损失。** 用户提供论文第 V-D 节、式 (12)–(13) 使用 CNN/Sigmoid 得到重要性分数，按预算保留 top-k，并将 `任务损失 + ε exp(Σκ−B)` 联合优化；没有互信息或 KL 项。本实现结合软分数惩罚与 STE hard-top-k，硬筛选控制真实包长。
2. **X→Z→Xpre 可以实现。** 输入是整个 8×16 历史窗口，输出一个 4 维向量，或从一个 8 维候选向量中选择若干分量。未来预测误差反传到编码器；部署不传输历史序列或未来预测轨迹。本轮 Xpre 具体为未来算力及两个出向链路可用度，不包含全部未来队列状态。
3. **PPO 可以和 compressor 联合训练。** 策略损失和预测损失均能到达编码器/筛选器，已用梯度测试验证。两个种子中，联合版编码器/筛选器参数确实改变，冻结对照完全不变，且两者起始权重一致。部署 actor 只用真正收到的 Z、age/missing 和公共元数据。

带宽成本已加入环境 reward，按真实发送字节计费：每 32 B 扣 1 个 reward 单位，包含包头、掩码与部分在途数据。自适应 budget actor 选择 k=1/2/3，使带宽成本确实随动作变化；固定包长时这个惩罚不能教会策略减少维数。

## 主测试结果

共享上报容量 64 kbit/s。下表为 100 ms 周期、两个训练种子与三个测试场景的均值；checkpoint 仅按验证 reward 选择。50/200 ms 下各方法的 SLA 均值同样为 18.03%。

| 方法 | 平均每包 B | 实发 kbit/s | 质量与 deadline 联合达标率 | 每请求 reward |
|---|---:|---:|---:|---:|
| 16 维统计量 + PPO | 80.00 | 19.65 | 18.03% | −0.9755 |
| 固定 4 维 + 联合 PPO | 32.00 | 7.86 | 18.03% | −0.9355 |
| importance 8 选 3 + 联合 PPO | 32.00 | 7.86 | 18.03% | −0.9355 |
| importance 8 选 3，冻结压缩器 | 32.00 | 7.86 | 18.03% | −0.9355 |
| 随机 8 选 3 + 联合 PPO | 32.00 | 7.86 | 18.03% | −0.9355 |
| importance + PPO 选择 k | 27.14 | 6.67 | 18.03% | −0.9315 |
| **公共规则，完全不上报** | **0** | **0** | **18.03%** | **−0.9089** |

因此，较小报文相对统计量得到更高的加权 reward，来自通信扣分减少；它没有击败零上报规则。不能用这张表宣称学到了有用的网络感知路由压缩。

## 为什么不能把平稳称为有效收敛

- 无热启动 pilot 中，路由分布长期接近均匀，entropy 约 2，昂贵大模型被大量采样，验证表现随种子/argmax 排序波动。完整 pilot 与源码快照均保留。
- 所有方法统一接受 20 epoch 的公开规则热启动后，验证 SLA 始终约 26.78%。12 个模型都通过末段 SLA/reward 平稳阈值，但策略的 entropy 和参数仍在变化。
- 对最后 checkpoint 的两个训练种子，在测试轨迹 251、100 ms 上，真实 Z 与零 Z 的动作一致率均为 **100%**；它们与公共规则的动作也完全一致，SLA 均为 **22.7347%**。零 Z 检查保留了 age/missing/public，并同时在完全相同观测上比较反事实动作。
- 5 个固定包长方法的两个种子均选中了 **update 0**，即热启动完成时的 checkpoint；自适应版种子 7 选 update 0，种子 17 选 update 55。测试 last 后各方法仍是同样的 SLA。
- importance 联合版在这批 720 个验证窗口中，两个种子各只有 **1 种选中掩码**。评分/筛选模块存在且可训练，但尚未展示随输入变化的选择优势。

这说明当前已跑通训练管线，却没有验证出策略有效利用 Z，更没有证明 PPO 找到了好的网络感知策略。

## 预测分支学到了什么

在固定的独立预测验证窗口上，最后 checkpoint 的 MSE：

| 方法 | MSE，两个训练种子均值 |
|---|---:|
| 训练集均值未来模板，无输入历史 | 0.04881 |
| 保持最新观测不变 | 0.09636 |
| 固定 4 维联合版 | 0.04538 |
| importance 8 选 3 联合版 | 0.04597 |
| importance 8 选 3 冻结版 | 0.04531 |
| 随机 8 选 3 联合版 | 0.04662 |
| 统计量预测器 | 0.04423 |

压缩表征的预测器略优于不使用历史的均值基线，说明有一定预测价值；但 importance 联合版没有在本轮优于全部对照。预测 MSE 下降没有自动转化为路由改善。自适应模型的固定 k=3 与实际 budget actor 选择下 MSE 分开保存在验证日志中。

## 失败原因诊断

单条测试轨迹 251 上，公共规则与免费即时当前状态启发式都成功 557/2450，但只是各任务类型的收益抵消：

| 任务类型顺序 | 公共规则成功数 | 即时状态启发式成功数 |
|---|---:|---:|
| 1 | 158 | 167 |
| 2 | 117 | 111 |
| 3 | 120 | 144 |
| 4 | 162 | 135 |

公共规则有 704 次拒绝、1158 次完成超时、31 次按时但质量不达标；即时启发式有 922 次拒绝、970 次完成超时、1 次按时质量不达标。两者都没有终点未完成任务。

各任务 nominal work 约 1.5–3.6 ms，而公共规则完成时延中位数约 79–87 ms，主要损失来自拥塞/排队。即时启发式不是最优策略或严格上界，也不含未来信息，不能因一个轨迹的总 SLA 相同就断定环境没有网络感知优化空间。

下一轮应先解决路由策略对队列状态、Z 和自身动作历史的利用，以及延迟任务收益的归因；再检验 importance filter 的独立收益。继续减小维数或只增加训练 epoch，不能替代这些检查。
